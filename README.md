# Seller Insight · 亚马逊经营统计看板

参考电商 BI 看板的浅色布局，面向亚马逊卖家的静态经营看板。无框架、无外部字体、无 CDN、无服务器接口。示例商品及数据均为虚构，不包含原参考文件中的真实经营数据。

## 使用

下载所有文件，双击 `index.html` 即可。或在本目录运行 `python3 -m http.server 8080`，访问 http://localhost:8080 。

支持经营总览、每日销售趋势、SKU 排名、商品明细排序、广告统计、销售目标、站点/日期/商品筛选、CSV 模板下载及导入导出。支持手机屏幕。

## 数据

点击「数据与口径」下载 CSV 模板。UTF-8 编码；每行代表一个日期、站点、店铺、SKU 的汇总数据，重复组合会被拒绝。支持 US/USD、UK/GBP、DE/EUR、JP/JPY。一次只统计一个站点，不换汇。导入前请将业务与广告报告按日期及 SKU 汇总匹配；不直接兼容所有亚马逊原始报表。

必填列：`date,marketplace,asin,sku,product,sales,orders,units,sessions,adSpend,adSales,impressions,clicks`。日期为 YYYY-MM-DD；金额为无货币符号的非负数字；数量为非负整数。单文件不超过 15 MB / 50,000 行。

ACOS = 广告花费 / 广告销售额；TACOS = 广告花费 / 总销售额；ROAS = 广告销售额 / 广告花费；转化率 = 订单 / 访问次数。先汇总后计算，零分母显示 —。广告归因窗口与业务报告可能不同，广告销售超过总销售时不绘制销售结构拆分。剩余销售额不应直接视作自然销售。

销售明细仅保存在当前页面内存，不上传；刷新后恢复演示数据。原「目标监控」页面更改筛选后清空汇总目标；新增 SKU 管理的目标及跟进记录会保存在本浏览器，详见下方说明。未对接亚马逊后台，不含利润、库存、退款或环比分析。

## SKU 经营管理（2026-11-10）

按「SKU 维度产品经营管理」思维导图新增 SKU 管理首页，原有总览、商品、广告和目标页面保留。

- 店铺 → 产品链接 → SKU：店铺经营汇总、链接展开、搜索与红黄绿状态筛选。
- 各 SKU 独立设置销售额或销量目标；目标周期由顶部开始/结束日期决定，统计截至日可独立选择。
- 显示实际完成、目标差额、完成率、时间进度、线性期末预估；缺日单独提示，不将缺记录认定为已确认零销量。
- 周期内进度比 = 完成率 / 时间进度；默认 ≥90% 绿灯、70%–90% 黄灯、<70% 红灯；可按 SKU 生命周期单独设置。周期结束以是否达成 100% 判断，缺目标和未开始单独显示。
- 显示 SKU 广告花费、广告销售、ACOS、TACOS、ROAS，提示高 TACOS、花费无产出及进度与投入需核查；广告类型拆分尚无数据，不生成虚构拆分。
- 近期销售比较两个等长窗口，每段最多 7 天，数据不完整不作趋势判断；规则提示并非因果判断。
- 保存负责人、截止日期、跟进状态和处理结果，保留最近 100 次历史；可导出当前清单 CSV 和管理 JSON 备份、合并恢复。

CSV 可增加 `store`（店铺）与 `parentAsin`（父产品链接）两列，原必填列不变。未提供时分别使用「未指定店铺」和单个 ASIN，不自动推断父子关系；同站点不同店铺的同名 SKU 隔离处理。CSV 导出保留可选列。

演示模式提供虚构目标并显著标记；导入模式不会自动生成经营目标。目标按数据模式/站点/店铺/SKU/周期隔离，跟进记录按数据模式/站点/店铺/SKU 隔离；更换同身份数据前请核对目标是否仍适用。

管理目标和跟进保存在浏览器 localStorage，仅供同浏览器使用，清理网站数据可能丢失，请导出备份。管理备份不包含销售明细，恢复时当前已存在记录优先保留。销售 CSV 仍只保留在页面内存中，刷新会恢复演示销售数据。没有团队同步或亚马逊 API 对接。

新增 `sku-core.js`（纯计算）、`sku.js`（交互）、`sku.css`（样式）、`sku.test.cjs`（边界测试）。运行：

```sh
node --test core.test.cjs sku.test.cjs
```
